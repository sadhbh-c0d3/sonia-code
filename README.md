## Overview

Sonia is a highly specialised human cognitive system optimised for **complex systems, pattern recognition, deep technical reasoning, research, invention, and solving problems that other people have already decided are impossible**.

The system was deployed to production approximately 25 years ago without complete documentation.

For most of its operational lifetime, Sonia was unaware that the underlying architecture was autistic and ADHD.

The system nevertheless operated successfully in production across multiple environments, including:

* low-level systems
* operating systems
* kernel development
* cybersecurity
* distributed systems
* algorithmic trading
* FPGA integration
* financial mathematics
* cryptography
* blockchain
* WebAssembly
* R&D
* technical leadership
* startup development

The system is currently undergoing extensive self-documentation.

# Core Architecture

Sonia uses a **highly parallel cognitive architecture** with strong pattern-recognition capabilities.

The system does not necessarily process information in the sequential order expected by the surrounding environment.

Instead, multiple threads of thought may execute concurrently.

This can produce exceptional performance when the workload is sufficiently interesting, meaningful, or technically complex.

It can also produce:

* context switching
* unexpected topic changes
* loss of the original thread
* excessive detail
* difficulty verbalising intermediate reasoning
* accidental race conditions between thoughts
* occasional infinite loops

These are known behaviours.

They are not necessarily bugs.

Some are features.

Some are features that occasionally behave like bugs.

# AuDHD Scheduler

The scheduler is non-deterministic.

It may behave approximately as follows:

```text
if task_is_interesting:
    engage_hyperfocus()

elif task_is_important_but_boring:
    search_for_dopamine()

elif task_is_extremely_difficult:
    become_interested()

elif task_is_timed:
    panic()

elif task_is_a_HackerRank_test:
    question_everything()

elif another_topic_is_more_interesting:
    switch_thread()

else:
    create_Jira_board()
```

The Jira board may temporarily restore system stability.

The Jira board may also become an object of hyperfocus.

Use with caution.

# Communication Layer

The internal cognition layer is not guaranteed to map cleanly onto the language layer.

Internal state may contain:

```text
Thought A
Thought B
Thought C
Pattern D
Memory E
Connection F
Question G
New hypothesis H
```

The communication subsystem may attempt to serialise these into:

```text
Sentence 1
Sentence 2
Sentence 3
```

Potential race conditions may occur.

Known symptoms include:

* saying something different from what was intended
* forgetting which thought was being communicated
* assuming something was already explained when it was only thought
* changing topic without noticing
* returning to previous topics
* providing excessive context
* difficulty answering "tell me about a time when..."
* difficulty retrieving memories according to externally imposed categories

Writing provides a useful debugging interface.

Recommended workflow:

```text
Think
↓
Write
↓
Read
↓
Inspect
↓
Reorganise
↓
Rewrite
↓
Publish
```

Cost:

**High time and energy consumption.**

Benefit:

**Significantly improved communication accuracy.**

# Known Issues

### Issue #001 — Timed Coding Tests

System may perform poorly under artificial time constraints.

This does not necessarily indicate inability to write code.

Possible causes:

* ADHD-related attention regulation
* excessive exploration of possible solutions
* inability to enter hyperfocus quickly
* distraction
* pressure
* difficulty switching from exploratory mode to execution mode

Recommended workaround:

```text
Warm up
↓
Solve several problems
↓
Enter technical flow state
↓
Run assessment
```

---

### Issue #002 — Behavioural Interviews

System does not reliably store career experiences as STAR-format interview responses.

System stores:

```text
Architecture
Patterns
Technical decisions
Problems solved
Systems built
Lessons learned
```

System does not necessarily store:

```text
"Tell me about a time when you demonstrated leadership."
```

Recommended workaround:

**Ask what was built, what problem existed, and what changed.**

Avoid assuming that inability to retrieve a suitable anecdote means inability to perform the underlying behaviour.

---

# Philosophy

Sonia does not believe that different cognitive architecture necessarily implies inferior cognitive ability.

The system strongly rejects the assumption:

```text
Different ≠ Broken
```

Preferred model:

```text
Different architecture
        ↓
Different strengths
        ↓
Different limitations
        ↓
Different support requirements
        ↓
Same human worth
```

The goal is not to make every human operate identically.

The goal is to make the environment accessible enough that different humans can contribute.
